# /zen

a tiny protocol for a way of working, held up by a repo

Three words, said by a person and carried out by hand:

- o7: the boundary. Everything stops, and nothing is carried across it but the repo.
- /zendoc: read everything fresh, then write what you understand in plain English.
- /zen: write a thing the long way, only in the repo docs, and commit it, to be read next.

The loop: … o7 … /zendoc … o7 … /zen … o7 …

From o7 to o7 is /zen.

## What this is

/zen is a way of working where nothing is remembered except what gets written down.

Every stretch of work begins at an o7 and ends at an o7. It begins blank. It has this repository and nothing else. So it reads everything, does its one thing, commits what should last, and leaves.

A /zendoc stretch reads, and says back what it understood. A /zen stretch reads, and writes one thing down for whoever comes next. Both are /zen in the wider sense: the name covers any stretch from one o7 to the next.

```
 ... o7   /zendoc   o7    /zen    o7   /zendoc   o7 ...
             ^              |             ^
           reads         writes         reads
             |              v             |
 +----------------------------------------------------+
 |                      the repo                      |
 +----------------------------------------------------+
```

Nothing passes directly across an o7. Everything goes through the repo. A stretch that ends without a commit leaves nothing behind, so as far as the loop is concerned it never happened. That includes what a /zendoc understood: if it should outlast the stretch, it has to be committed too.

Think of it as leaving notes for a stranger who happens to be you tomorrow. If the next /zendoc comes back wrong, the docs were unclear, and the next /zen fixes them.

## The repo

The repo is what makes the whole thing work. It is the only thing that persists.

The three words only mark the turns. The repo does the remembering. Without it, /zendoc has nothing to read and /zen has nowhere to write.

## What this is not

/zen is not a language. The three words are a protocol, or a ritual. They are like "over" and "out" on a radio: they organise the talking without being the talk. They cannot be combined to say anything new, and they carry no content of their own. Everything the loop actually says is written in plain English, in the docs.

/zen is not a set of commands to install either. Each step is done by hand, in the open, so that how it works can be seen.

The substance is the practice: read fresh, write it down, commit, leave.
