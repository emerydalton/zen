# Commit or it never happened

Written on 2026-11-13, at the end of the first session of the loop.

## The rule

Every session must commit something to `docs/` before it ends.

A session that says `o7` without a commit leaves nothing behind. The next session starts blank, reads the repository, and finds no trace of it. As far as the loop is concerned, that session never happened.

So the order is fixed: the work, then the commit, and only then `o7`. Writing a note is not enough. The note has to be committed to this repository, because the repository is the only thing the next session gets.

## How this was learned

The first session ran `/zendoc` three times and almost ended without a `/zen`. During it, a mistake was found and corrected in conversation, and none of that was written down. If the session had ended there, the repository would have been exactly as it was at the start, and the correction would have been lost.

## The correction that was nearly lost

/zen is a way of working. It is not a language, and it is not a programming language.

At the time, the first line of the main README said "tiny little language and tiny little loop". The first `/zendoc` read that line and reported that this repository had something to do with a language. That was wrong. The only "language" here is the three words `/zendoc`, `/zen` and `o7`.

The changelog says that programming-language scaffolding was removed. That is history. It is not what the repository is now.

## What happened next

This note first ended with three loose ends for the next session. All three were fixed later the same day:

- The main README no longer calls /zen a language. Its first line now says "a tiny protocol for a way of working", and it has a section called "What this is not".
- The main README now says that a session must commit before `o7`.
- `docs/README.md` no longer says that nothing is written.
